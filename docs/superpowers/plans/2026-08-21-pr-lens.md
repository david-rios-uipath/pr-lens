# pr-lens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fully local TypeScript tool that ranks a repo's open PRs by review-easiness across multiple score dimensions, consumable as a CLI (agents) and a local GitHub-styled web app (humans).

**Architecture:** pnpm monorepo. `packages/core` is a pure library (GitHub GraphQL client, multi-dimension heuristic scoring engine, path-based component derivation, zod report schema). `packages/cli` (`pr-lens`) orchestrates scan → report → consumption and serves the built web app with a tiny local API. `apps/web` is Vite + React + @primer/react, dark default, rendering the locally generated report.

**Tech Stack:** TypeScript (strict), pnpm workspaces, zod, commander, vitest, ESLint 9 + typescript-eslint (strictTypeChecked), Vite, React 18, @primer/react.

**Spec:** `docs/superpowers/specs/2026-08-21-pr-lens-design.md`

## Global Constraints

- pnpm only; never npm/yarn. Node >= 20. All packages ESM (`"type": "module"`).
- Strict, type-checked linting: typescript-eslint `strictTypeChecked`; `@typescript-eslint/no-unnecessary-type-assertion: error`; `no-explicit-any: error`; lint runs with `--max-warnings 0`.
- No live GitHub API in tests — recorded fixtures only.
- Tokens come from `GITHUB_TOKEN` env or `gh auth token`; never written to disk or sent to the browser.
- Report path: `.pr-lens/report.json` under cwd; `.pr-lens/` is gitignored.
- Scan is all-or-nothing: never overwrite a good report with a partial fetch (write temp file, then rename).
- Commit after every green test cycle. Commit messages end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 3: Scoring engine + reviewability factors (incl. inert codeComplexity)

**Files:**
- Create: `packages/core/src/scoring.ts`
- Modify: `packages/core/src/index.ts`
- Test: `packages/core/test/scoring.test.ts`

**Interfaces:**
- Consumes: `PrData`, `FactorBreakdown`, `DimensionScore` from Task 2.
- Produces:
  - `interface FactorResult { value: number; reason: string }` (value in [0,1]).
  - `interface Factor { name: string; weight: number; evaluate(pr: PrData): FactorResult }`
  - `const REVIEWABILITY_FACTORS: readonly Factor[]` — names exactly: `diffSize`, `filesTouched`, `ciStatus`, `reviewState`, `age`, `changeNature`, `mergeability`, `codeComplexity`.
  - `function evaluateDimension(factors: readonly Factor[], pr: PrData): DimensionScore` — weighted mean of values over factors with weight > 0, scaled to 0–100, rounded to integer; breakdown includes **every** factor (weight-0 ones too, so the placeholder is visible).
  - `function scorePr(pr: PrData, weightOverrides?: Record<string, number>): Record<string, DimensionScore>` — returns `{ reviewability: ... }`; overrides replace matching factor weights by name.
  - `function affinityScore(shares: Record<string, number>, component: string): number` — `Math.round((shares[component] ?? 0) * 100)`.

Factor formulas (implement exactly; `now` is injectable for tests: `evaluate` uses `pr.updatedAt` against `Date.now()` — structure `age` factor as created by `makeAgeFactor(now: () => number)` and export `REVIEWABILITY_FACTORS` built with the real clock, plus `makeReviewabilityFactors(now)` for tests):
- `diffSize` (w 0.25): `total = additions + deletions`; `value = 1 - Math.min(1, Math.log10(1 + total) / Math.log10(2001))`; reason `` `${total} lines changed` ``.
- `filesTouched` (w 0.15): `value = 1 - Math.min(1, Math.log10(1 + changedFiles) / Math.log10(51))`; reason `` `${changedFiles} files` ``.
- `ciStatus` (w 0.2): SUCCESS→1 "CI green", NONE→0.6 "no CI", PENDING→0.3 "CI pending", FAILURE→0 "CI failing".
- `reviewState` (w 0.15): `isDraft`→0 "draft"; CHANGES_REQUESTED→0.2 "changes requested"; `approvals > 0`→1 `` `${approvals} approval(s)` ``; else 0.7 "awaiting review".
- `age` (w 0.1): hours since `updatedAt`: <1→0.8 "very fresh"; <24→1 "updated today"; <72→0.8 "updated this week"; <168→0.6 "updated within 7d"; else→0.3 "stale".
- `changeNature` (w 0.1): classify from `pr.files` paths — docs-only (every path matches `/\.(md|mdx|txt)$/i` or starts `docs/`), tests-only (every path matches `/(^|\/)(tests?|__tests__|spec)\//` or `/\.(test|spec)\.[cm]?[jt]sx?$/`), config-only (every path matches `/\.(json|ya?ml|toml)$/` and `changedFiles <= 5`). Any category → 1 with reason `"docs-only"` / `"test-only"` / `"config-only"`; empty `files` or no category → 0.4 "mixed changes".
- `mergeability` (w 0.05): MERGEABLE→1 "mergeable", UNKNOWN→0.7 "mergeability unknown", CONFLICTING→0 "has conflicts".
- `codeComplexity` (w **0**): always `{ value: 0, reason: "not implemented — algorithm TBD" }`. Placeholder per spec; do not compute anything.

### Task 4: Component derivation

**Files:**
- Create: `packages/core/src/components.ts`
- Modify: `packages/core/src/index.ts`
- Test: `packages/core/test/components.test.ts`

**Interfaces:**
- Consumes: `PrFile` from Task 2.
- Produces:
  - `const CROSS_CUTTING = "cross-cutting"`
  - `interface PrComponentInfo { shares: Record<string, number>; primary: string; secondary: string[] }`
  - `interface ComponentDerivation { components: { name: string; prCount: number }[]; perPr: Map<number, PrComponentInfo> }`
  - `function componentKey(path: string): string` — split on `/`; if first segment ∈ {`src`, `packages`, `apps`, `libs`, `lib`} and there are ≥2 segments, return `seg0/seg1`; if the file has no directory, return `"root"`; else return `seg0`.
  - `function deriveComponents(prs: { number: number; files: PrFile[] }[]): ComponentDerivation`

Algorithm for `deriveComponents`:
1. Per PR, sum changed lines (`additions + deletions`, min 1 per file) per `componentKey`; shares = per-key lines / total lines.
2. Merge always-co-occurring keys: for each pair (a, b) each appearing in ≥2 PRs, if the set of PR numbers containing a equals the set containing b, union them (union-find); merged component name = member keys sorted, joined with `"+"`. Recompute shares under merged names (sum member shares).
3. Primary = key with the largest share, but if the largest share < 0.35 → primary = `CROSS_CUTTING` (keep real shares). Secondary = other keys with share ≥ 0.15, sorted by share desc.
4. `components` = every merged name that is primary or secondary for ≥1 PR, plus `cross-cutting` if used; `prCount` = number of PRs where it is primary or secondary; sorted by prCount desc then name.
